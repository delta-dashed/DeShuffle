# Закреплённая текущая книга, план и архив «Города»

Репозиторий `delta-dashed/DeShuffle`, ветка `codex/town-guide`. Основа — исправления PR #15, включая `f5509f3`. Новый код ещё не развёрнут из локальной среды. Итоговый SHA и результаты тестов указаны в сообщении о завершении.

## Поведение

Сверху закреплена **«Текущая книга · название»**. В ней видны автор, материалы и файлы, план N+1, число эссе и ссылка на постоянную карточку книги. Первые две кнопки идут строго в порядке **«План чтения» → «Архив»**; ниже — действия текущей книги и общие действия каталога. При смене книги обновляются заголовок, содержимое и ID действий эссе/управления. Когда чтение не выбрано, старые действия книги убираются.

[Discord разрешает одну закреплённую тему в форуме](https://support.discord.com/hc/en-us/articles/6208479917079-Forum-Channels-FAQ). План и архив остаются отдельными темами, их место среди обычных книг определяет сортировка Discord. Фиксированного порядка трёх тем над остальными бот не обещает. Из плана и архива есть обратные кнопки в закреп.

Существующий `catalog:<guild>` становится текущей книгой с прежними ID и страницами-переходами. Создаются только `catalog:<guild>:plan` и `:archive`; новые установки не создают `:current`. Если прежний `:current` уже был опубликован, его сообщения и страницы превращаются в переходы к закрепу с сохранением ID. Удалённые старые сообщения не создаются заново. Неподтверждённая отправка старого `:current` сначала восстанавливается по журналу, чтобы не оставить заблокированную очередь отправок.

Разделы используют существующий тег «Каталог». Ручные названия и права Discord не перезаписываются. Управляемое название текущего закрепа следует за книгой, пока организатор не переименует тему вручную. При потерянном ответе старой отправки прежнее имя принимается за управляемое только при точном совпадении с сохранённым намерением отправки. Если занят единственный pin, чужая тема остаётся закреплённой, разделы публикуются, предупреждение доступно в `/club diagnose` и журнале.

План показывает N встреч по книге + обсуждение эссе, реальные предстоящие/идущие встречи, публичные границы чтения, ближайшие синки, всю очередь и отдельно предложения. Приватные планы ведущих не читаются. Архив содержит только прочитанные книги и количество опубликованных эссе. Даты из старого поля книги не подставляются вместо события обсуждения. Статусы книг, встречи, порядок, автостатусы и исходные эссе этот переход не изменяет.

Отправка идёт через прежний журнал восстановления потерянных ответов Discord, последовательно под общим lock. Повтор и перезапуск сохраняют ID. После обычного полного обновления восстанавливаются удалённые разделы и ссылки на них. Редактирование книги сначала обновляет её карточку, затем только изменившиеся разделы; неизменившиеся разделы в этой операции не запрашиваются через REST. Полный периодический refresh проверяет их отдельно.

Схема БД остаётся **13**; новой миграции нет. Если сервер ещё до PR #15, при обновлении применяются его миграции и правила развёртывания: [BOOKCLUB_FAST_CONTROLS_ROLLOUT.md](BOOKCLUB_FAST_CONTROLS_ROLLOUT.md).

Проверки: полный прогон **856 тестов прошёл**, включая 30 тестов тем «Города». Проверены грамматика Python 3.10 и `git diff --check`. Покрыты порядок кнопок, смена текущей книги и всех её действий, пустое чтение, сохранение старых ID, переход старого `:current`, потерянные ответы корней/страниц и перезапуск. Discord и модель в тестах подменены, SQLite временная. При имитации GET=100 мс для 13 книг полный refresh занял 2009 мс / 17 GET, точечное изменение — 286 мс / 2 GET; реальное время проверить на сервере.

## Обновление на сервере

1. Зафиксировать установленный SHA, единственный рабочий контейнер, текущий каталог и его страницы. Сохранить снимок книг/статусов/порядка, публикаций/эссе и завершённых импортов/бюджета.
2. Остановить сервис. Сделать и проверить закрытую резервную копию volume `/data`, конфигурации и `.env`; сохранить прежний образ. Секреты и копии в Git не добавлять.
3. Получить проверенный commit, собрать и запустить тем же Compose-проектом. Не запускать старый дублирующий контейнер. Не запускать scan, модель, авторизацию и не менять счётчики/лимиты импортера.
4. Обычная публикация после запуска создаст только недостающие план и архив. Проверить прежний ID закрепа, его заголовок и текущую книгу, существующий тег «Каталог», порядок кнопок «План чтения» / «Архив», обратные переходы и сохранение ручных названий. Если другой пост закреплён вручную, решить вручную, нужно ли освобождать pin для текущей книги.
5. Проверить содержимое по снимку: текущая книга, вся очередь и предложения, архив только прочитанного, корректные реальные даты встреч, отсутствие приватных текстов. Старые ссылки страниц и прежнего `:current` должны вести в закреп. На тестовых книгах проверить переключение заголовка и всех пяти действий при выборе новой текущей книги, отсутствие старых действий при пустом чтении и отсутствие дублей после повторного refresh/перезапуска.
6. Сверить неизменность рабочих ID книг/эссе, исходных привязок, завершённых импортов и бюджета. Зафиксировать реальную задержку сохранения отдельно от локального тестового замера.

## Откат

Остановить сервис и сохранить текущее состояние. При возврате к `367c883` схема 13 совместима: прежний код снова отрисует путеводитель и отдельный `:current`. При возврате к `f5509f3` прежний код отрисует общий каталог, а дополнительные темы останутся в Discord и потребуют решения организатора об их дальнейшем использовании. Не удалять рабочие книги и эссе ради отката. При возврате к коду до PR #15 использовать его инструкцию отката; восстановление SQLite из копии не откатывает уже совершённые действия Discord.
