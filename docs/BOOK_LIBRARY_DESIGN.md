# Библиотека файлов и план чтения

Предложение по итогам обсуждения 15 сентября 2026. Загрузка файлов и создание нового репозитория пока не включены.

## Источники

Для своего каталога лучше хранить метаданные издания, происхождение файла и результат проверки отдельно от PDF/EPUB. Сам факт бесплатного скачивания не подтверждает право повторно публиковать файл; у каждого издания, включая перевод, нужно сохранять условия распространения. Для публичного зеркала подходят издания с подтверждённым разрешением или подходящим статусом общественного достояния.

- [Project Gutenberg](https://www.gutenberg.org/policy/permission): условия различаются для изданий и использования вне США. Для автоматической загрузки предусмотрены [каталоги, harvesting и зеркала](https://www.gutenberg.org/policy/robot_access.html); обычные страницы сайта не предназначены для массового обхода.
- [Standard Ebooks](https://standardebooks.org/contribute/producing-an-ebook-step-by-step): подготовка издания включает сверку со сканами печатного источника. Их [метаданные](https://standardebooks.org/manual/1.7.4/single-page) содержат ссылки на текстовый источник и сканы. Это полезный образец проверяемого происхождения, преимущественно для англоязычного каталога.
- [Флибуста](https://flibusta.is/) публикует ссылку на OPDS-каталог и описывает наполнение пользователями. Это возможный источник поиска метаданных; наличие файла само по себе не подтверждает его полноту или разрешение на зеркалирование. Состояние конкретной выгрузки OPDS ещё не проверено.
- Страница [@flibusta_bot](https://t.me/flibusta_bot) существует, но выдача книг и принадлежность бота администрации библиотеки в этой работе не проверялись. Действующая документация Telegram описывает [общение ботов](https://core.telegram.org/api/bots/bot-to-bot): в личном чате соответствующий режим должен быть включён у обоих ботов. Поэтому доступность страницы бота ещё не означает возможность автоматического подключения. Сессию личного Telegram-аккаунта в Discord-бот добавлять не требуется на этапе проектирования.

## Что проверять в файле

1. Правильные автор, название, язык, переводчик, издание и ISBN при наличии. Не объединять разные переводы только по названию.
2. Файл действительно является PDF/EPUB, а не HTML-страницей ошибки. Ограничить размер, время загрузки и распаковки.
3. EPUB: целостность ZIP, наличие метаданных, оглавления, всех файлов из spine и ссылок на главы. PDF: открытие всех страниц, отсутствие оборванных объектов и неожиданных пустых страниц; для сканов — сверка последовательности страниц.
4. Сопоставить главы, начало и окончание с оглавлением и независимым источником того же издания. Проверить признаки ознакомительного фрагмента. Число страниц у разных изданий не является надёжным критерием полноты.
5. Сохранить размер, SHA-256, источник, дату загрузки и отчёт. Хеш подтверждает неизменность скачанного файла; полноту произведения он не доказывает.

Полезные состояния: «файл исправен», «полнота не проверена», «сверено с источником», «проверено организатором». Автоматическая проверка не должна обещать полное произведение только потому, что файл открывается.

## Устройство репозитория

В Git — карточки изданий, источники, условия распространения, контрольные суммы и отчёты. Файлы — в Releases или отдельном хранилище с постоянными ссылками. Книга в Discord получает короткие ссылки «Читать PDF» и «Скачать EPUB». Первую реализацию ограничить выбором и проверкой конкретного издания организатором; затем добавлять автоматическое обновление уже проверенных источников.

## Число синков

«Первый», «Второй» и «Третий синк» — повторяющиеся события расписания. Их названия не являются номерами встреч конкретной книги. Сейчас бот показывает ближайшие экземпляры и их актуальные даты из Discord отдельно от индивидуальных встреч книги.

Для полноценного планирования нужен начальный синк книги и последовательность отдельных проведённых встреч. По умолчанию: 3 встречи чтения, следующая — обсуждение эссе. Длинная книга может получить 5 встреч чтения и шестую по эссе. Перенос события сдвигает дату, но не номер уже проведённой встречи. Завершение одной повторяющейся серии нельзя приравнивать к завершению книги.

Предложение по объёму: считать слова основного текста, исключив оглавление и издательские страницы; делить на согласованный объём чтения между синками, округлять вверх и выравнивать границы по главам. Пример расчёта: 90 000 слов / 30 000 слов между встречами → 3 встречи чтения + обсуждение эссе. Эти числа иллюстрируют алгоритм, а не рекомендуемый всем темп. Сложность книги и неравные интервалы между синками требуют поправок организатора. Для PDF-скана сначала нужен надёжный текст или ручная оценка.

Бот должен предлагать план на проверку. Самостоятельно назначать обсуждение эссе на третий синк, создавать события или менять уже согласованные даты по размеру файла не следует.
