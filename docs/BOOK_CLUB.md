# Книжный клуб в ReShuffle

Это расширение существующего бота, запускаемого через `Shuffle.py`. Стек сохранён: Python 3.10+, discord.py 2.x, SQLite, asyncio. Новая БД, веб-интерфейс и второй бот не нужны. Клуб по умолчанию выключен.

## Повторный аудит и доработка эссе

На начало этой доработки дерево Git уже содержало незакоммиченные изменения книжного клуба: пакет `bookclub`, интеграцию в `Shuffle.py`, конфигурацию, документацию и тесты. Это существующий код, а не результат текущей доработки. Применимых AGENTS.md в проекте и родительских каталогах не найдено. Базовый прогон до новых изменений: **49 тестов прошли**. Изучены исходный промпт, публикации, учет эссе, хранение и восстановление, README, Docker и настройки; секреты не выводились.

## Автоматическая настройка

В `.env` задайте `BOOKCLUB_ENABLED=true`, а `BOOKCLUB_CONFIG_FILE` оставьте пустым. После запуска `python Shuffle.py` владелец сервера или участник с правом **Manage Server** выполняет `/club setup`. Команда доступна и до первоначальной настройки клуба. Если slash-команда ещё не появилась, используйте существующий `!sync`; доступен также префиксный вариант `!club setup`.

Первый запуск создаёт категорию **Книжный клуб**, текстовые каналы **вестник** и **площадь**, форумы **город** и **либрариум**, голосовой канал **Ротонда**. Затем сохраняет их ID в SQLite, создаёт теги форумов, подготавливает вебхук эссе, публикует каталог с кнопками и описания Вестника и Площади, включает публикации и личные напоминания клуба. Книги, встречи и участников чтения вы добавляете отдельно. Администратор, впервые настроивший клуб, добавляется в организаторы.

| Команда | Результат |
|---|---|
| `/club setup` | Создать структуру или проверить и исправить существующую |
| `/club setup check_only:true` | Проверить каналы, права, роли, обязательные теги, состояние публикаций и вебхуков; ничего не менять |
| `/club setup category:категория` | Использовать выбранную существующую категорию и её доступы при создании недостающих каналов |
| `/club setup repair_permissions:true` | Явно восстановить недостающие разрешения самого бота; права людей и ролей сохраняются |

Для создания форумов и тегов заранее включите **Community** и выдайте боту **Manage Channels** и рабочие права клуба, перечисленные ниже; **Administrator** не требуется. Обычный `/club setup` не меняет разрешения существующих каналов, включая разрешения самого бота. Если их не хватает, команда сообщает об этом. Исправьте доступы вручную или явно используйте `repair_permissions:true`; этому варианту дополнительно нужен **Manage Roles**.

Настраивайте роли и отдельные разрешения в Discord: **Изменить канал → Права доступа**. Можно скрыть категорию от `@everyone`, дать выбранной роли просмотр, отдельно разрешить создание публикаций или только ответы. Бот не синхронизирует существующие каналы с категорией и не сбрасывает ваши настройки при повторной команде или перезапуске. Новые каналы в выбранной существующей категории копируют её доступы людей без изменения разрешений на отправку и подключение; отдельно выдаются необходимые права боту. Только при создании новой категории с нуля используется начальный открытый шаблон, а Вестник доступен для публикаций организаторам.

Команды клуба, кнопки и подсказки проверяют доступ к форуму книг и его истории. Снятие роли прекращает личные уведомления и участие в подборе ведущего, сохраняя историю и запись об участии. Для эссе отдельно проверяются права форума эссе; создание новой темы требует разрешения создавать публикации, ответ в уже существующей теме — отправлять сообщения в тредах. Административная диагностика и восстановление остаются доступны организатору при ошибке прав бота. Вызов обычных префиксных команд вне каналов клуба предлагает slash-вариант с приватным ответом.

Повторная команда использует сохранённые ID, сохраняет пользовательские названия, восстанавливает подтверждённо удалённые каналы и карточки и продолжает незавершённую настройку. Одноимённые чужие каналы не присваиваются. Отказ в доступе не считается удалением. При восстановлении старого клуба бот использует его существующую общую категорию; если прежнюю категорию удалили или её доступы определить нельзя, он предложит выбрать категорию с нужными правами. Сохранившиеся каналы бота возвращаются в выбранную замену с сохранением собственных разрешений. Историю удалённого канала Discord восстановить нельзя.

При потере ответа создания бот ищет канал по сохранённому случайному маркеру и продолжает с тем же ID. Если результат установить нельзя, он приостанавливает создание: после проверки сервера и только при действительном отсутствии канала повторите `/club setup retry_missing:true`. Создание каналов выполняется исключительно по команде; перезапуск и фоновая сверка сами структуру сервера не разворачивают. [Создание каналов](https://docs.discord.com/developers/resources/guild#create-guild-channel), [изменение каналов](https://docs.discord.com/developers/resources/channel#modify-channel).

## Ручная конфигурация и локальная проверка

1. Установите зависимости в виртуальное окружение. Проверенная среда: Python 3.13, discord.py 2.7.1. Версия SDK закреплена в requirements: безопасный транспорт использует проверенные внутренние точки подключения библиотеки.

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe -m unittest discover -s tests -v
   .\.venv\Scripts\python.exe -m bookclub --check-config bookclub.example.json
   ```

   Последняя команда проверяет синтаксис и ограничения настроек во временной БД. Она не читает токен и не подключается к Discord. Проверка каналов и прав требует `/club diagnose` уже на выбранном тестовом сервере.

2. Если вы используете уже существующие каналы или хотите ограничить список серверов, скопируйте `bookclub.example.json` в `bookclub.json` или каталог данных. Замените все примерные ID. Ключ объекта `guilds` — ID сервера. Для автоматической настройки файл не обязателен. Названия каналов бот не использует для поиска.

   | Поле | Назначение | Тип |
   |---|---|---|
   | `news` | Вестник: организационные объявления о датах, переносах, отменах и изменениях | Текстовый |
   | `chat` | Площадь: общение и предложения | Текстовый |
   | `books` | Город: каталог и темы книг | Форум |
   | `essays` | Либрариум: авторские эссе | Форум |
   | `voice` | Ротонда: постоянное место встречи | Голосовой |

   Каналы должны быть разными и принадлежать соответствующему серверу. При подключении существующих каналов сохраняются их названия и разрешения. `/club setup` создаёт недостающие ресурсы; права бота исправляет только с `repair_permissions:true`. **Вестник** предназначен для организационных объявлений вручную. Бот оставляет одно описание канала и не публикует туда обычное расписание, текущую книгу и сроки. Даты хранятся в карточках книг и нативных событиях. **Площадь** — флуд и свободное общение; бот оставляет одно пояснение, служебные напоминания отправляет лично.

3. Настройте `organizer_roles` и/или `organizers`. Это списки ID ролей и людей, уполномоченных управлять клубом. Владелец сервера также считается организатором. Наличие прав Administrator или Manage Guild само по себе не назначает организатором существующего клуба; оно разрешает команду настройки структуры `/club setup`. Участники книги задаются отдельно через `/club join` и `/club participant`.

4. `reminder_role: null` означает напоминание всем участникам конкретной встречи. Если указан ID роли, обычное напоминание за 30 минут получают только участники этой встречи с этой ролью. Роль не добавляет человека в чтение. Подготовка ведущего и обязательное эссе не зависят от этой подписки. Бот никому не выдаёт роли.

   `essay_webhooks: true` (по умолчанию) включает создание новых шапок эссе с ником и аватаркой автора через вебхук; при архивном переносе такое же оформление получают все части текста и сообщения с файлами. Создавать URL вебхука вручную и добавлять его в конфигурацию не требуется: бот создаст или найдёт свой вебхук при первом таком нажатии. `false` сохраняет публикации от имени бота. Переключение режима не перепубликует и не удаляет существующие темы; для старого импорта предусмотрена отдельная команда `restyle` с предпросмотром. Если прав для вебхука не хватает, бот объясняет проблему, а не меняет способ публикации молча.

5. Настраиваемые интервалы:

   | Поле | По умолчанию | Назначение |
   |---|---:|---|
   | `participant_minutes` | 30 минут | Участникам до встречи |
   | `preparation_hours` | 24 часа | Ведущему, если план не готов |
   | `escalation_hours` | 3 часа | Ведущему и организаторам, если план не готов |
   | `offer_hours` | 24 часа | Срок ответа кандидата, ограниченный началом встречи |
   | `essay_hours` | 24 часа | До явно заданного срока эссе; ещё одно уведомление в сам срок |
   | `timezone` | Europe/Moscow | Ввод дат без смещения и отображение |

   Формат даты: `2027-01-18 18:30` либо ISO 8601 с явным смещением. Пример не создаёт задания. Неоднозначное местное время при переводе часов требует UTC-смещения. В SQLite сохраняются Unix timestamps в секундах. Базовые окна пн/ср 18:30 и пт 17:00 показаны как подсказка: автоматического календаря повторяющихся встреч нет.

6. Измените `.env` только при готовности запускать расширение:

   ```dotenv
   BOOKCLUB_ENABLED=true
   BOOKCLUB_CONFIG_FILE=A:/path/to/bookclub.json
   ```

   Существующие `DISCORD_TOKEN` и `RESHUFFLE_DATA_DIR` продолжают работать. Изменения JSON применяются после перезапуска. Неизменённые значения файла не отменяют ID, восстановленные `/club setup`; явно изменённый ID заменяет прежнюю привязку. При смене назначения новые карточки публикуются в новом канале, старая история остаётся на месте. Неизменённая конфигурация сохраняет версии заданий; изменённые интервалы пересчитывают только будущие задания. Если файл задан, его `guilds` ограничивает разрешённые серверы: при удалении сервера из файла история остаётся в SQLite, но обработка клуба прекращается. Пустой объект `guilds` отключает все серверы. Если путь к файлу не задан, бот использует настройки SQLite и разрешает первичную настройку администраторам серверов. `BOOKCLUB_ENABLED=false` отключает всё расширение.

## Временный импорт старых эссе через Codex

Импортер переносит выбранные эссе из старого текстового канала или форума, включая его публичные треды, в настроенный форум эссе клуба. Он работает отдельными командами и по умолчанию выключен. Обычные сообщения, упоминания бота и кнопки эссе не вызывают Codex. Клуб должен быть настроен заранее через `/club setup` или ручной конфиг.

### Включение на время переноса

1. На машине, где запущен бот, установите **Codex CLI 0.152.1 или новее**. Если бот работает в Docker, CLI нужен внутри того же контейнера. Вход в Codex на вашем личном компьютере не авторизует бот на другой машине.
2. Скопируйте [bookclub.import.example.json](../bookclub.import.example.json) в `bookclub.import.json` или в каталог данных. Замените `allowed_user_ids`, `allowed_guild_ids`, `allowed_channel_ids` на реальные числовые ID. В последнем списке указываются исходные каналы или форумы; их публичные треды входят в сканирование. Личные сообщения и приватные треды не импортируются. Не используйте форумы назначения клуба как источник.
3. Укажите путь в `.env`: `BOOKCLUB_IMPORT_CONFIG_FILE=/data/bookclub.import.json` для Docker либо абсолютный путь на хосте. Требуется `BOOKCLUB_ENABLED=true`. В JSON измените `enabled` на `true` и перезапустите бот.
4. Команды импорта доступны только человеку из списка, на разрешённом сервере, с правами владельца, Administrator или Manage Server. Роль организатора клуба сама по себе доступ к импорту не даёт. Проверяются также текущие права на чтение источника и форума назначения.

Файл читается один раз при запуске. Изменения `enabled`, списков доступа, модели и лимитов требуют перезапуска. Через Discord включить импортер, расширить доступ или пополнить бюджет нельзя. После переноса установите `enabled: false` и перезапустите бот; оставьте SQLite для сохранения истории переноса и счётчиков.

### Вход и команды

| Команда | Действие |
|---|---|
| `/club import login` | Начать вход на машине бота и получить ссылку OpenAI с одноразовым кодом |
| `/club import status` | Проверить вход, оставшиеся запуски, учтённый расход и последние планы |
| `/club import inventory [source] [page]` | Полный перечень доступных активных и архивных публичных тредов: по 10 на странице и полный JSON, решения и прогресс чтения; без Codex |
| `/club import prepare thread:ID decision:included title:… author:… confirm:true [source]` | Подтвердить книжный тред и его данные; вместо `title`/`author` можно выбрать существующую `book`; `excluded` исключает, `pending` возвращает на проверку |
| `/club import preview [source] [before] [thread] [after] [cursor]` | Проверить фрагмент подтверждённой очереди; явный `thread` позволяет сначала ознакомиться с неподтверждённым тредом. JSON и точное продолжение без Codex и расхода квоты |
| `/club import scan [source] [before] [thread] [after] [cursor]` | Только после подтверждения подготовки и отдельного решения о лимите: один запрос плана у Codex по подтверждённому фрагменту; ознакомительные снимки не допускаются |
| `/club import review run:ID` | Повторно открыть сохранённый план и полный JSON со снимком исходных сообщений; модель не вызывается |
| `/club import restore run:ID file:план.json confirm:true` | Восстановить `failed`/`unknown` по проверенному человеком JSON, сохранив журнал и израсходованную квоту; публикации не создаются |
| `/club import apply run:ID confirm:true` | Применить проверенный план и скопировать эссе в форум; модель не вызывается |
| `/club import restyle run:ID [confirm]` | Без `confirm` показать план исправления оформления завершённого импорта; с `confirm:true` заменить подтверждённые копии внутри прежних тем, без Codex |

После `login` откройте выданную [страницу входа OpenAI](https://auth.openai.com/codex/device) в своём браузере, войдите в нужный аккаунт ChatGPT и введите выданный код на странице OpenAI. Пароль, токены и cookies боту отправлять не нужно. Device-code login — бета-функция: её нужно разрешить в настройках безопасности ChatGPT или настройках рабочего пространства. Бот ожидает подтверждения до 15 минут; затем можно начать новый вход. [Официальная документация входа](https://learn.chatgpt.com/docs/auth).

Ссылка и код, результаты проверки и JSON плана отправляются приватным ответом slash-команды. Снимок JSON содержит тексты исходных сообщений: храните его как копию архива с теми же ограничениями доступа. Авторизацию сохраняет и обновляет сам Codex CLI в отдельном профиле; код бота не читает файл с токенами. По умолчанию профиль расположен в `bookclub-codex-profile` рядом с SQLite. `codex_home` позволяет задать другой отдельный каталог. Личный `~/.codex` и каталог с пользовательскими `config.toml` или `hooks.json` для импортера не подходят. На Linux каталог создаётся с правами `0700`; на Windows ограничьте ACL учётной записью службы бота. Файлы авторизации не должны попадать в Git, образ Docker или публичные резервные копии.

Ожидаемые ошибки клуба показываются приватно с конкретной причиной, в том числе когда Discord оборачивает их в ошибку выполнения команды. Неизвестные ошибки получают общее сообщение; служебные подробности не раскрываются участникам.

### Что входит в план и перенос

Сначала выполните `inventory`: команда перечисляет доступные активные и архивные публичные треды независимо от лимита входа модели. Она показывает решения «включён», «исключён», «нужен выбор человека», уже импортированные исходные сообщения и прогресс чтения. Полный перечень тредов не означает, что все эссе прочитаны. Сохранённое решение связано с ID источника и треда; переименование его не отменяет.

Для проверки незнакомого треда используйте `preview thread:ID`. Параметр принимает строковый ID, включая архивный тред. Ознакомительный снимок помечен `preparation_confirmed: false`: он не создаёт кандидатов книг и не разрешает анализ моделью. Первая строка источника служит подсказкой человеку; название и автор из неё автоматически не назначаются. После проверки выполните `prepare` с явными `title`/`author` либо сопоставлением `book`, решением и `confirm:true`. Неоднозначные «Сочинения» и похожие темы оставляйте на проверке, пока человек не установит книгу. Посты, не относящиеся к книгам, явно исключайте.

`preview` всего канала читает только подтверждённую очередь. Ответ показывает число сообщений, **подтверждённых книг в данном фрагменте**, размер JSON, предупреждения и `coverage`. Это не счётчик книг всего архива. Подготовка доступна при исчерпанной квоте и без авторизации Codex. При достижении лимита чтение останавливается по целым сообщениям; `continuation` содержит точный токен для `preview source:… cursor:…`. Он продолжает текущий тред, затем переводит к следующему. Продолжайте до конца очереди, включая пустые страницы с токеном, если в них были только пропускаемые сообщения. `cursor` нельзя совмещать с `thread`/`before`/`after`. Для ручного диапазона `before` и `after` — исключающие границы ID сообщений выбранного `thread`; завершение диапазона не означает прочтение всего треда. Если одно сообщение с контекстом не помещается, команда объяснит ограничение, без автоматического увеличения лимита.

**Новый лимит запусков и вызов `scan` согласуются отдельно после просмотра источников и метаданных.** Для подготовки оставшихся книг DeShuffle при израсходованном бюджете `legacy-essays-v1` используйте [контекст для серверного Codex с полным контрольным списком и командами preview](BOOKCLUB_IMPORT_PREPARATION.md). На этом этапе нельзя вызывать модель, менять счётчики или повторять завершённый импорт.

После отдельного разрешения `scan` передаёт Codex ограниченный снимок текста, ID сообщений и только подтверждённых книг, относящихся к этому фрагменту. Заголовки обсуждений и весь существующий каталог автоматически в кандидаты не превращаются. Codex возвращает только ссылки на предоставленные книги и сообщения. Авторство проверяется по ID из Discord; модель не придумывает авторов, названия, ссылки или новый текст эссе. Неуверенно распознанные сообщения остаются без переноса. Содержимое вложений модель не читает. Проверьте в плане книгу, автора, состав многочастного эссе и пометку **«новая книга»**. Новая книга появится только при применении плана, с подтверждёнными человеком метаданными. Следующий анализ требует свободного лимита запусков, который изменяется только в конфигурации.

При `apply` бот ещё раз читает оригиналы и проверяет авторов, текст, вложения, права доступа и форум назначения. Изменённый после анализа источник требует нового плана. При включённом `essay_webhooks` шапка, все части текста и сообщения с вложениями публикуются через вебхук с ником и аватаркой автора. Текст сохраняется без литературного редактирования. Это новые сообщения вебхука, поэтому они не становятся личными сообщениями автора с прежней датой. Служебные ссылки на оригиналы в шапку, текст и материалы новой книги не добавляются; ссылки, которые автор включил в само эссе, сохраняются. Новые сообщения сразу отправляются без служебных строк `bc:…`. До отправки SQLite сохраняет намерение публикации; после потерянного ответа бот проверяет отправителя, текст, вложения, кнопки и границу истории, затем привязывает единственное совпадение. При неопределённости повторная отправка запрещена. Исторические незавершённые сообщения прежних версий могут восстанавливаться по старым маркерам; после сохранения ID маркер убирается. Оригиналы сохраняются. Файлы копируются в пределах заданного объёма и ограничения Discord; для остальных в копии остаются имя файла и объяснение лимита.

Новые части эссе делятся по абзацам, строкам и словам, с пределом 1500 символов; лишь слово длиннее лимита приходится разрезать. Разделители остаются в сохранённом плане, а проверка опубликованного текста учитывает обрезание краевых пробелов Discord. Точный массив частей записывается до первой отправки части и используется после перезапуска. Уже опубликованные части сохраняют исторические границы, ID и вложения: повторный `apply`/`restyle` не переразбивает их и не запускает модель.

План, привязки исходных сообщений и этапы копирования записываются в SQLite. Повторное применение завершённого плана не создаёт дубликаты. После прерванного копирования используйте сохранённый `run`, а не новый платный `scan`: бот продолжит по журналу. При неподтверждённом отсутствии публикации может потребоваться существующий `/club repair` после ручной проверки. Перенесённые работы регистрируются в клубе и появляются в списке эссе книги. «Добавить своё эссе» открывает уже перенесённую работу, а «Открыть моё эссе» показывает личные работы и черновики. Автор или организатор может исправить ошибочную книгу через `/club essay correct:true`; сохранённый автор и внутренние связи с источниками не меняются.

### Восстановление неудачного анализа без нового запроса

Для запуска со статусом `failed` или `unknown` откройте `/club import review run:ID` и возьмите ID книг и сообщений из сохранённого снимка. Подготовьте JSON в UTF-8 размером не более 64 КиБ, содержащий только выбор существующих ID:

```json
{"essays":[{"book_ref":"source:ID_ТЕМЫ","message_ids":["ID_СООБЩЕНИЯ"]}]}
```

Замените примеры реальными значениями из снимка и проверьте состав эссе. Затем выполните `/club import restore run:ID file:план.json confirm:true`. Команда проверяет план теми же правилами, что и ответ модели: один автор на эссе, только предоставленные сообщения и книги, без повторов. Восстановленный запуск получает статус `review`; применение затем отдельно подтверждается через `apply`. Готовый или выполняющийся план этой командой не заменяется. SQLite сохраняет инициатора, время, прежний статус и SHA-256 плана. Счётчики запусков и резерв токенов не меняются, Codex не вызывается; ручное изменение SQL не требуется.

### Исправление уже перенесённых эссе

Для обновления рабочего контейнера и проверки результата используйте [актуальную инструкцию для Codex на сервере](BOOKCLUB_RELIABILITY_ROLLOUT.md). [Прежняя инструкция](IMPORT_FIX_ROLLOUT.md) описывает историческую замену обычных сообщений копиями вебхука.

Если прежняя версия импортировала только шапку с аватаром автора, выполните `/club import restyle run:ID`. Для завершённого запуска `done` команда покажет темы и число частей, которые потребуется заменить или восстановить. После проверки выполните ту же команду с `confirm:true`. Нужны включённый импортер, обычные права импорта и `essay_webhooks:true`; авторизация Codex и свободная квота не требуются.

Темы форума, авторство, связь с книгой, оригиналы и ответы участников сохраняются. Текст и файлы прежних подтверждённых копий сначала публикуются с ником и аватаркой автора, затем бот удаляет только проверенные старые копии из своего журнала. Новые сообщения получают новые ID и появляются в конце существующей темы; вернуть их прежнюю дату или позицию Discord не позволяет. Из шапки и копий убираются служебные ссылки, а из материалов книги — только точная ссылка, автоматически записанная прежним импортом. Ручные материалы не стираются. Если копии уже отправлены вебхуком, повторный `restyle` удаляет оставшиеся служебные маркеры редактированием существующих сообщений: их ID, порядок, файлы и реакции сохраняются. Удаляется только точная строка, добавленная ботом; похожий текст внутри самого эссе остаётся.

Проверка останавливается, если прежняя копия изменена, удалена без подготовленной замены, имеет другого отправителя или не совпадает состав вложений. Все замены подтверждаются до удаления старого текста. Ход исправления и пары старых/новых ID записываются в SQLite; повторная команда продолжает по журналу без повторного анализа. Архивная тема временно открывается и после обработки возвращается в архив; незавершённое восстановление этого состояния сохраняется для повторного запуска команды. Автоматически удалять отдельные лишние темы-черновики эта операция не будет.

### Диагностика ответа Codex

Адаптер читает итоговый JSON из файла `--output-last-message`, а при отсутствии файла — из завершённого `agent_message` потока JSONL. Одновременно проверяется успешное завершение, корректный usage и отсутствие вызовов инструментов. Неизвестный формат, незавершённый ответ, повторяющиеся ключи JSON и недопустимые числа отклоняются; произвольный JSON внутри текста не подбирается как план.

Ошибка содержит короткий код диагностики; в логах остаются размеры, номер строки, известные типы событий и источник финального ответа. Сырой stdout/stderr, текст эссе, токены авторизации и неизвестные значения полей в диагностику не записываются. Причину прежнего серверного отказа точно установить нельзя: stdout того запуска не сохранился. Новая диагностика поможет определить причину следующего отказа без повторного запроса ради исследования старого случая.

### Лимиты и остановка

| Поле JSON | По умолчанию | Назначение |
|---|---:|---|
| `enabled` | `false` | Разрешить команды импорта после перезапуска |
| `budget_id` | `legacy-essays-v1` | Имя сохраняемого общего бюджета переноса |
| `max_runs` | `1` | Максимум запусков модели для этого бюджета на всех разрешённых серверах вместе |
| `max_accounted_tokens` | `100000` | Ограничить резерв и учтённый расход перед следующими запусками |
| `max_messages` | `200` | Максимум сообщений в одном снимке |
| `max_threads` | `30` | Максимум публичных тредов в одном снимке |
| `max_input_bytes` | `48000` | Ограничить размер снимка для анализа |
| `max_attachment_bytes` | `20000000` | Общий объём копируемых вложений; `0` оставляет только имена файлов и пояснение лимита |
| `timeout_seconds` | `180` | Максимальное время работы процесса анализа |
| `executable` | `codex` | Исполняемый файл CLI на машине бота |
| `codex_home` | `null` | Отдельный профиль рядом с БД либо явно указанный путь |
| `model` | `null` | Использовать выбор CLI; строка задаёт конкретную модель |

Один процесс бота выполняет не более одного анализа одновременно. Бюджет резервируется **до** запуска модели и сохраняется при ошибке, таймауте или перезапуске. Повторное включение импорта не обнуляет расход. Новая порция работы разрешается администратором хоста через увеличение лимитов или новый `budget_id` с перезапуском; менять `budget_id` при каждом старте не нужно. После ошибки бот не запускает новый анализ автоматически. Используется встроенный провайдер OpenAI, функция неограниченных переподключений CLI выключена. Обычные HTTP/SSE-повторы самого CLI могут происходить в пределах общего таймаута: версия 0.152.1 запрещает переопределять настройки встроенного провайдера, поэтому нулевое число таких повторов не обещается.

**`max_accounted_tokens` не является жёстким пределом токенов одного ответа.** У CLI нет подтверждённого ограничения такого типа. Импортер ограничивает число запусков, размер входа и время процесса, затем учитывает доступные данные usage. Неизвестный расход не возвращает резерв. Возможный расход уже начатого ответа сохраняется даже при остановке локального процесса. [Неинтерактивный режим и события usage](https://learn.chatgpt.com/docs/non-interactive-mode).

CLI запускается с чистым окружением без токена Discord, в отдельном временном рабочем каталоге, с режимом `read-only`, отключёнными доступными shell, web search, hooks, plugins, apps и агентными функциями. Перед анализом проверяется поддержка нужных параметров. Это ограничения CLI, а не обещание полноценной изоляции всех инструментов или жёсткого лимита токенов. Результат модели дополнительно проверяется по исходным ID; произвольные команды и текст из него бот не выполняет.

Для Docker соберите вариант с CLI: `docker build --build-arg INSTALL_CODEX=true --build-arg CODEX_VERSION=0.152.1 -t reshuffle-codex .`. Обычный образ обходится без Codex. Запустите выбранный образ с постоянным приватным `/data`, файлом конфига по указанному в `.env` пути и профилем `/data/bookclub-codex-profile`. Вход выполняйте уже после запуска через `login`; авторизацию не добавляют на этапе сборки.

Реальные вызовы модели, авторизация аккаунта, чтение Discord-архива и перенос сообщений при разработке не выполнялись. Проверки адаптера и конфигурации используют подставные процессы и временные файлы; отдельная проверка установленного CLI обращалась только к справке и списку feature flags.

## Discord: предпосылки и права

Форумы требуют включённого Community; это необходимо сделать вручную. В форуме предусмотрено одно закреплённое обсуждение, поэтому закрепляется только каталог, а страницы идут сообщениями внутри него. Чужое закрепление бот не заменяет. См. [официальный FAQ форумов](https://support.discord.com/hc/en-us/articles/6208479917079-Forum-Channels-FAQ).

В Developer Portal включите Server Members Intent и Message Content Intent, уже необходимые ReShuffle. В коде также включены Guilds, Voice States и Guild Scheduled Events. Пригласите приложение со scopes `bot` и `applications.commands`.

Для каналов клуба нужны View Channel, Send Messages, Read Message History; для форумов — Send Messages in Threads и Manage Threads (закрепление, статусы и восстановление доступности тем). В Вестнике для закрепления общих правил нужно отдельное **Pin Messages**. Если права нет, бот продолжает обновлять карточки, сообщает о недостающем праве и повторяет закрепление после его выдачи. Голосовые события требуют View Channel, Connect, Create Events; Manage Events нужен для работы с событиями, созданными организатором. Голосовое подключение самого бота для клуба не требуется. Administrator не нужен. Форумы с обязательными тегами поддерживаются после `/club setup`: при создании поста бот сразу передаёт нужные теги. [Scheduled Events](https://support.discord.com/hc/en-us/articles/4409494125719-Scheduled-Events), [правила threads](https://docs.discord.com/developers/topics/threads).

Ограничьте права Вестника по правилам клуба: участникам — чтение, боту и ведущим/организаторам — публикация. После первоначального создания настройте права в Discord по своему усмотрению. Бот сохраняет ручные разрешения; явное `repair_permissions:true` касается только его собственных недостающих прав. Чужие сообщения бот не редактирует.

Для режима `essay_webhooks: true` в форуме эссе боту дополнительно нужны **Manage Webhooks** (создать, найти и получить свой вебхук) и **Manage Threads** (восстанавливать доступ к архивированным темам). `/club diagnose` проверяет оба права. Участникам Manage Webhooks не требуется. Ник и аватар задаются параметрами конкретной отправки, а не сменой общего профиля вебхука: одновременные действия разных авторов не смешиваются. [Execute Webhook](https://docs.discord.com/developers/resources/webhook#execute-webhook).

## Миграция и запуск

Перед обновлением остановите экземпляр бота и сохраните копию всего каталога `RESHUFFLE_DATA_DIR`. Миграция автоматическая и добавочная: таблицы `bc_*` и собственный журнал `bc_migrations`, без изменения старых таблиц, JSON-файлов и SQLite `user_version`. Черновики хранятся в этой же БД; ограничьте доступ к файлу и резервным копиям администраторам хоста.

Миграция 2 добавляет в `bc_essays` признаки `managed` и `submitted`. Все существующие записи получают `managed=0`, `submitted=1`: старые авторские публикации и ссылки продолжают засчитываться. Новая тема, созданная кнопкой, получает `managed=1`, а до сообщения автора — `submitted=0`. Пересоздавать БД и переносить старые эссе не требуется.

Миграция 3 добавляет `webhook_id` в публикации и таблицу `bc_webhooks` для ID вебхука форума и незавершённого создания. Секретные URL и токены вебхуков не записываются в БД или JSON. Старые публикации с `webhook_id=null` продолжают обрабатываться как сообщения бота.

Миграция 4 добавляет журнал создания каналов `bc_setup_resources` и снимок последнего внешнего конфига `bc_config_imports`. Настройки и незавершённые действия сохраняются после перезапуска; прежние таблицы, книги, встречи и эссе остаются на месте.

Миграция 5 добавляет `bc_import_runs`, `bc_import_budgets` и `bc_import_sources`: планы импорта, устойчивые счётчики и привязки оригиналов к копиям. Авторизация Codex хранится отдельно от SQLite. После перезапуска незавершённый анализ получает состояние `unknown`, а незавершённый перенос возвращается к проверенному плану для явного продолжения.

Миграция 6 добавляет `bc_forum_tags` (назначения тегов и Discord ID), `managed_name` в публикации и `name` в журнал каналов. Ручные названия отличимы от последнего названия, назначенного ботом. Старые темы без этой метки не переименовываются произвольно. Все связи книг, встреч и эссе сохраняются.

Миграция 7 добавляет `bc_import_plan_restores` для аудита восстановленного человеком плана, `bc_import_restyle_audit` для подтверждённых замен архивных копий и `bc_import_restyle_threads` для тем с незавершённым возвратом в архив. Бюджеты, существующие планы, привязки источников и темы не пересоздаются. Сама миграция не меняет сообщения; массовое исправление завершённого импорта выполняется через `restyle confirm:true`.

Миграция 8 добавляет необязательное поле `bc_books.reading_meetings`: плановое количество встреч по книге, к которому в интерфейсе прибавляется одна встреча для разбора эссе. Отсутствующее значение означает стандартные 3 встречи чтения + обсуждение эссе. Даты не создаются автоматически. Изменение плана сохраняет темы, встречи, эссе, авторов и конфигурацию импорта.

Миграция 9 сохраняет решения человека о книжных источниках, охват подготовки и курсоры предпросмотров. Миграция 10 добавляет журнал намерений публикаций `bc_publication_intents`, точное разбиение эссе `bc_import_chunk_plans`, управление автостатусом и его аудит, явные роли встреч и подтверждение состояния событий. Существующие книги получают выключенный автостатус; их текущие статусы, ID тегов и завершённые импорты не меняются.

Запуск остаётся прежним: `python Shuffle.py`. Работает **один процесс на токен и каталог данных**. SQLite защищает конкурирующие изменения; внешний Discord I/O дополнительно сериализуется по серверу внутри процесса.

После запуска команды синхронизируются существующим механизмом ReShuffle; при необходимости используйте `!sync`. Сам запуск может выполнять старые функции shuffle: для испытаний используйте отдельное приложение/тестовый сервер и отдельный каталог данных.

Для автоматического развёртывания выполните `/club setup`. При ручной конфигурации организатор сначала выполняет `/club diagnose`, затем `/club publish`. До успешного `setup` или `publish` клуб не создаёт каталог, Вестник и карточки и не рассылает напоминания. Явная команда `meeting_add` создаёт событие даже до публикации — это её назначение. После публикации бот обновляет сохранённые сообщения и отправляет личные уведомления.

Dockerfile включает пакет `bookclub`. В Compose уже есть постоянный volume `/data`; при автоматической настройке достаточно сохранённой SQLite. Для ручного конфига разместите в нём `bookclub.json` и укажите `BOOKCLUB_CONFIG_FILE=/data/bookclub.json`, либо подключите файл отдельным read-only volume. Сам файл конфигурации с рабочими ID не встраивается в образ. `docker compose up --build -d` выполняйте только при принятом решении о деплое.

## Управление книгой и план встреч

В начальном сообщении темы книги есть кнопки **«Управление книгой»** и **«Встречи»**. Они открывают приватные панели организатора. Открытие не ждёт общего lock, занятого обновлением всех карточек, и использует доступный кэш Discord. Перед любой записью бот заново проверяет реальные права, доступ к форуму и актуальную версию книги; остальные участники не могут изменить книгу или расписание через эти кнопки.

В **«Управлении книгой»**:

- Выпадающий список меняет статус: **Предложено → В очереди → Читаем → Прочитано**. Можно выбрать любой из этих статусов. Одновременно читается одна книга: прежде чем начать следующую, завершите прежнюю или верните её в очередь. Статус обновляется в карточке, каталоге и тегах; смена статуса не отменяет встречи. Любой ручной выбор статуса, включая выбор того же значения, выключает автостатус.
- **«План встреч»** задаёт количество **N встреч по книге + 1 отдельная встреча для разбора и обсуждения эссе**. Например, введите `3`, чтобы получить план из четырёх встреч. Допустимы N от 1 до 100; пустое поле возвращает стандартные 3 встречи. Он виден в карточке и панели встреч.
- **«Изменить описание»** открывает форму названия, автора, места в очереди и материалов. Срок эссе вычисляется из даты обсуждения по общему правилу клуба. Названия тем, вручную изменённые в Discord, сохраняются по прежним правилам.
- **«Включить автостатус»** показывает правило N+1 и требует подтверждения. У существующих книг автоматика после обновления выключена: организатор сначала проверяет план и роли конкретных встреч. Включение сохраняет текущий статус и ждёт нового подтверждённого изменения состояния события. Кнопка **«Выключить автостатус»** возвращает ручное управление. У новых книг автоматика включена по умолчанию.

План N + 1 описывает формат чтения. Изменение числа не назначает даты, не создаёт серию событий и не удаляет уже назначенные встречи. Конкретные события задаются отдельно: организатор выбирает даты и границы чтения. В управлении каждой встречей явно задаётся роль **«По книге»** или **«Обсуждение эссе»**. Название «Разбор эссе», часть книги и последняя глава не заменяют выбор роли. Старые встречи автоматически не классифицируются; новые по умолчанию относятся к чтению.

При включённом автостатусе подтверждённый фактический старт связанного голосового события переводит книгу в **«Читаем»**. Подтверждённое завершение события, пропущенного во время отключения, также доказывает начало. Назначение даты и наступление времени по часам статус не меняют. Для **«Прочитано»** должны завершиться ровно **N встреч по книге и одна по эссе**. Отменённая встреча не выполняет место в плане: требуется замена. Черновики, лишние события, отсутствующая роль или неподтверждённое состояние блокируют завершение; исчезновение события/404 не считается доказанной отменой.

Повторы и запоздалые события не откатывают **«Прочитано»**. Уже известные события после ручного включения автостатуса не меняют старую книгу задним числом. Правило одной текущей книги сохраняется: автоматика не снимает «Читаем» у другой книги ради старта следующей. При автоматическом переходе обновляются карточка, каталог и существующий тег статуса; ручное изменение статуса выключает автоматику до отдельного повторного включения.

В **«Встречах»** показаны план книги и фактическое количество предстоящих, текущих, завершённых и отменённых событий. Выберите встречу в списке; если их больше 25, доступны страницы. **«Добавить встречу»** открывает форму названия, даты, длительности, части книги и последней главы. Время интерпретируется в часовом поясе клуба; в заполненных формах сохраняется UTC-смещение.

У конкретной встречи есть **«Дата и длительность»**, **«Название и главы»**, ссылка на событие Discord и отмена с отдельным подтверждением названия и даты. Та же панель открывается кнопкой **«Управление встречей»** в её обычной карточке. Перенос меняет прежнее событие; ведущему требуется подтвердить новые условия, как и при `/club move`. Изменение границы чтения снимает готовность плана. Отмена доступна только для будущей встречи, сохраняет историю и прекращает её напоминания.

Если другой организатор или событие Discord изменились после открытия формы, бот предложит открыть управление заново. Повторное подтверждение той же формы создания проверяет сохранённый запрос и не создаёт второй экземпляр события. При неопределённом результате создания используется `/club recover_event`.

После обновления рабочего бота проверьте миграцию 8 и выполните `/club publish`, чтобы новые кнопки появились на прежних карточках. При необходимости `!sync` обновит параметр `reading_meetings` существующей команды `/club book_edit`. Внешние конфиги, права каналов и бюджет Codex менять не требуется. Описания Вестника и Площади остаются прежними; обычное расписание в Вестник не публикуется.

## Кнопки каталога и загрузка списка

После обновления бота выполните `!sync`, если нет новой команды `/club library import`, и `/club setup` для тегов и обновления карточек. Каталог закреплён в форуме книг. В его начальном сообщении и в ответе `/club books` есть две кнопки:

- **Добавить книгу** — форма названия, автора и материалов. После отправки создаётся книга со статусом «Предложено» и её отдельный пост форума. Ответ содержит ссылку на тему. Нужны просмотр форума книг и разрешение создавать в нём публикации.
- **Загрузить список** — организатор вставляет список до 4000 символов. Более длинный список приложите файлом к `/club library import file:`; достаточно выбрать файл в параметре slash-команды, отдельный канал для загрузки не нужен.

Простой формат [books.example.txt](books.example.txt): одна книга на строку, название и автор разделены `|`. Необязательное третье поле — материалы.

```text
Мастер и Маргарита | Михаил Булгаков
Дюна | Фрэнк Герберт
```

CSV/TSV: заголовок `title,author,materials` (или `название,автор,материалы`), разделитель — запятая, точка с запятой либо табуляция; столбец материалов необязателен. JSON: массив объектов, например `[{"title":"Дюна","author":"Фрэнк Герберт"}]`. Файл должен быть в UTF-8, не больше **64 КиБ и 100 книг**. Произвольные тексты без разделения названия и автора требуют предварительного форматирования. Codex и другие модели при этой загрузке не вызываются.

Сначала бот показывает приватный постраничный предпросмотр. Только кнопка **Добавить книги** сохраняет список и публикует темы. Ошибки формата не приводят к частичному добавлению в БД. Повторы по названию и автору пропускаются с учётом регистра и пробелов; существующие книги и материалы не перезаписываются. Новые книги добавляются по порядку со статусом «Предложено». Публикация после сбоя продолжается по сохранённым ID без повторного создания записей.

## Переименование и теги

Категорию, каналы, темы книг и эссе, а также теги можно переименовывать в Discord. Связи хранятся по ID. Повторная настройка запоминает текущие имена каналов для последующего восстановления. Изменение названия темы вручную не меняет название книги в каталоге: для этого используйте `/club book_edit title:`. Если имя темы всё ещё автоматическое, оно обновится вместе с книгой; ручное имя остаётся как задано.

`/club setup` создаёт теги:

| Форум | Теги |
|---|---|
| Книги | Каталог, Предложено, В очереди, Читаем, Прочитано |
| Эссе | Черновик, Эссе, Архив |

Статус книги задаёт её тег. Тема автора получает «Черновик», после его текста — «Эссе»; импортированные работы получают «Эссе» и «Архив». Переименованный тег сохраняет назначение. Пользовательские теги и их оформление сохраняются. Удалённый служебный тег восстанавливается при `/club setup`. При неоднозначном одинаковом названии или нехватке места команда сообщает проблему без удаления чужих тегов. Discord допускает 20 тегов форума и 5 тегов на теме. [Теги и изменение канала](https://docs.discord.com/developers/resources/channel#modify-channel), [теги при отправке вебхуком](https://docs.discord.com/developers/resources/webhook#execute-webhook).

## Сценарии

**Организатор.** Добавьте книгу; выставьте «В очереди» и её `position`, затем «Читаем». Если уже читается другая книга, сначала завершите её или верните в очередь. Добавьте участников или предложите им `/club join`. Создайте встречу с точными частью и последней главой, включая название главы при необходимости. Укажите срок эссе отдельным полем книги. Откройте карточку встречи: «Подобрать ведущего» предложит кандидата из добровольного пула. Либо используйте `offer` с выбором человека.

**Ведущий.** Участник чтения нажимает «Провести встречу» и затем «Подтверждаю». Адресное предложение принимается отдельной кнопкой с подтверждением; до этого видно «Ожидаем подтверждения». «Мой план» открывает ephemeral-ответ, доступный только текущему ведущему и организаторам. Поля: темы, вопросы, сцены/цитаты, заметки. Количество пунктов не оценивается. «Опубликовать вопросы» открывает отдельную форму: впишите только выбранный фрагмент, который действительно хотите показать в теме книги. Остальные поля никогда не включаются в публичные карточки.

После заполнения отметьте «План готов». При редактировании содержимого готовность снимается. Во время встречи план доступен той же кнопкой, включая мобильный Discord. После встречи сохраните короткие итоги отдельной формой; длинный протокол не требуется. План и итоги доступны после завершения события.

**Замена и перенос.** Организатор снимает назначение через `replace`, выбирает нового человека и дожидается принятия. Новый ведущий начинает с пустого плана; `handover` явно копирует предыдущий черновик и снимает готовность. Существующий новый план передача не перезаписывает. Старые кнопки и формы больше не дают прежнему ведущему доступ. Перенос времени, окончания или голосового канала из Discord либо `/club move` требует повторного подтверждения текущим ведущим. Ему приходит личное уведомление; до принятия новое время не считается согласованным.

Ротация сначала уменьшает нагрузку от уже принятых/ожидающих будущих назначений, затем выбирает того, кто дольше не вёл; при равенстве — меньший устойчивый Discord ID. История учитывает только наблюдавшийся переход активной встречи в завершённую с подтверждённым ведущим. Отказавшиеся, истёкшие кандидаты, отсутствующие на встрече и вышедшие с сервера исключаются. Если кандидатов не осталось, это явно видно в карточке. Автоматического подбора до нажатия кнопки нет; после отказа/истечения уже начатый подбор продолжается.

**Участник и эссе.** В начале темы книги или в карточке встречи нажмите **«Добавить своё эссе»**. Если у вас уже есть зарегистрированная работа по этой книге в форуме эссе, включая архивный импорт, кнопка открывает её. Опубликованная работа имеет приоритет перед случайно созданным пустым черновиком; существующие дополнительные темы не удаляются. Если работы ещё нет, бот создаёт пост: заголовок содержит книгу и ваше отображаемое имя, а шапка указывает вас автором и связывает пост с книгой. Повторное нажатие открывает ту же тему. Поиск по заголовку для этой связи не нужен.

Постоянная кнопка **«Открыть моё эссе»** в карточках книги и встречи показывает приватные ссылки на все ваши зарегистрированные работы и черновики по этой книге в текущем форуме эссе. Она ничего не создаёт и не открывает архивные темы для записи. Достаточно доступа к чтению форума и истории; право отправлять сообщения не требуется. Если работы нет, ответ предлагает кнопку добавления. Удалённые записи помечаются недоступными; отказ Discord в доступе не становится поводом создавать дубликат.

Откройте полученную ссылку и отправьте эссе обычным сообщением от своего имени. Можно писать несколькими сообщениями, приложить файл или дать ссылку. Вы редактируете собственные сообщения средствами Discord. Сразу после создания пустая шапка не считается опубликованной работой и не отменяет напоминания. Когда вы отправляете сообщение с текстом, вложением или ссылкой, бот учитывает работу и обновляет ссылки в карточке книги и списке **«Эссе участников»**. Сообщения других людей в вашей теме не засчитываются как ваше эссе. Содержательная оценка текста не выполняется.

В карточке книги все опубликованные работы расположены до длинных материалов и встреч. Кнопка **«Эссе участников»** открывает полный список со ссылками и авторами; длинный список разбивается на страницы без ограничения числа работ. Кнопки находятся в корне темы, даже когда сама карточка занимает несколько страниц. Карточка встречи также содержит ссылку **«Книга и эссе участников»**.

Новая шапка публикуется вебхуком с ником участника на сервере и его текущей аватаркой. Это оформление сообщения; техническим отправителем остаётся вебхук, а не личный аккаунт. Реальный автор эссе определяется по ID нажавшего человека и не меняется от ника, аватарки или переименования темы. Участник пишет от себя и редактирует собственные сообщения обычным способом. Шапку вебхука обновляет бот через API вебхука; вручную редактировать её как своё сообщение участник не сможет. Заголовок ограничен 100 символами, поэтому длинное название книги сокращается с сохранением имени автора. Ранее созданные шапки бота сохраняются. [Создание через webhook](https://docs.discord.com/developers/resources/webhook#execute-webhook), [редактирование webhook-сообщения](https://docs.discord.com/developers/resources/webhook#edit-webhook-message).

Ручной путь сохраняется: создайте пост «Название книги · Название эссе» или зарегистрируйте старый пост/сообщение через `/club essay`. Так же можно добавить несколько разных работ одного автора. При однозначном названии бот регистрирует новый авторский пост автоматически; при неоднозначности предлагает выбрать книгу через команду. Подтвержденная связь хранится по ID и не меняется от переименования. `correct=True` исправляет ошибочную связь. При удалении поста или зарегистрированного сообщения запись помечается удаленной; другая работа этого автора продолжает засчитываться.

После отключения бот сверяет новые посты, включая архивированные, и содержимое созданных им тем. Старые материалы до момента первоначальной настройки клуба можно зарегистрировать вручную ссылками; отдельный временный импортер позволяет скопировать выбранные эссе по предварительно проверенному плану. Обычная сверка оригиналы не перепубликует. Выход автора с сервера не стирает его эссе. Без однозначно назначенного события обсуждения эссе срок не вычисляется. Уведомления получают только участники чтения без опубликованной работы.

**Завершение книги.** Организатор завершает фактическую встречу в Discord. При включённом и проверенном автостатусе завершение всех N+1 встреч переводит книгу в «Прочитано»; организатор также может выбрать этот статус вручную, выключив автоматику. Карточки, материалы, эссе и обсуждения сохраняются. Автоархивирование поста не меняет статус книги, бот не блокирует обсуждения после прочтения.

## Восстановление и пределы надёжности

Фоновая сверка выполняется каждые 30 секунд. Время встречи всегда проверяется по Discord; локальные timestamps — кэш для планирования. Gateway обрабатывается через документированные `on_scheduled_event_*`; перед обработкой обновления снова читается текущее событие, чтобы опоздавшее уведомление не откатило состояние. Дополнительно есть REST-сверка после запуска и перед отправкой. Если Discord недоступен, отправка откладывается; если она устарела, пропускается.

Задания имеют устойчивый ключ и версию объекта. Перенос/отмена/замена делают прежние задания неактуальными. При позднем назначении создаются только будущие пороги подготовки. При запуске все уже прошедшие задания пропускаются, а незавершённые отправки получают `unknown`; в работающем процессе допустимое опоздание ограничено 120 секундами. Уже выполненные задания не повторяются.

Ошибка обновления карточек не блокирует личные напоминания о встречах. Каждое событие повторно проверяется перед отправкой; при ошибке проверки именно его уведомление откладывается. Если не удалось сверить эссе, напоминания об эссе не отправляются по непроверенным сведениям. Переименование события сохраняет ещё не отправленное приглашение ведущему с исходным сроком. Продление уже идущей встречи не снимает ведущего и его доступ к плану.

Публикации резервируются до Discord API и сразу отправляются с чистым текстом. Намерение отправки в SQLite сохраняет канал, отправителя, границу истории, текст, вложения и кнопки. При потерянном ответе выбирается только одно проверенное совпадение; до любых последующих правок его ID сохраняется. При неоднозначности или неподтверждённом отсутствии новая отправка запрещена. Организатор проверяет `/club diagnose` и доступную историю; не удаляет журнал ради повтора. Исторические резервирования без намерения могут восстанавливаться по прежним маркерам, которые затем удаляются из сообщений. Для нативного события механизм маркера в описании сохраняется: при потерянном ответе используйте `recover_event`; если события точно нет, создайте его вручную в Discord и привяжите.

Для вебхук-шапки до отправки сохраняется ID конкретного вебхука. Восстановление проверяет сохранённое намерение и ID отправителя: чужой вебхук с тем же именем не может присвоить эссе участнику. Форумные посты, сообщения бота и вебхука запрещают повторы POST после неопределённого сбоя; явный ответ Discord 429 допускает ожидание и повтор. Обычные сообщения дополнительно используют сохранённый nonce. Версия discord.py закреплена на 2.7.1, этот транспорт проверяется на уровне HTTP. Потерянный ответ создания самого вебхука восстанавливается по списку интеграций форума; неподтверждённое отсутствие требует ручной проверки. Если вебхук удалили, существующие эссе остаются связанными с авторами и доступными, но изменить старую шапку технически нельзя — это отражается в диагностике. Следующая новая тема сможет использовать новый вебхук; уже написанное эссе не дублируется.

Постоянные кнопки книги и встречи имеют устойчивые `custom_id`, не истекают по таймеру и заново регистрируются через `bot.add_view` после перезапуска. Права и принадлежность серверу проверяются при действии, а автор созданного эссе берется из текущего взаимодействия. Это соответствует механизму [persistent View в discord.py](https://discordpy.readthedocs.io/en/stable/interactions/api.html#discord.ui.View.is_persistent). Обычные кнопки поддерживаются API, поэтому реакции для создания эссе не требуются. [Компоненты Discord](https://docs.discord.com/developers/components/reference#button).

Абсолютное exactly-once внешних отправок не обещается. Между успешной отправкой DM и фиксацией в SQLite возможен сбой; повтор не выполняется автоматически, чтобы не создавать дубли, и отдельный получатель может остаться без уведомления. Есть также небольшое окно между последней REST-проверкой и отправкой, когда организатор может изменить событие. Недоступные личные сообщения и временные ошибки фиксируются в диагностике; публичного раскрытия черновика при ошибке нет. discord.py обрабатывает rate limits; повторную сверку выполняет фоновый цикл.

Если активная фаза события целиком прошла во время отключения бота, нельзя достоверно установить, кто фактически провёл встречу; такая встреча не добавляется в ротационную историю автоматически. События клуба не запускаются/завершаются по локальному таймеру: это делает ведущий в Discord. Если для голосового канала уже настроена старая автоматика shuffle, она продолжает работать по прежним правилам; для отдельной Ротонды её подключать не требуется.

## Каталог, общий формат и повторяющиеся синки

Сохранение в «Управлении книгой» теперь сразу обновляет приватную панель после проверки прав и записи в БД. Карточка книги, её тег и каталог обновляются приоритетно в фоне, без ожидания полного обхода клуба. При сбое публикации сохранённое изменение повторно применять не нужно: его подхватит сверка; `/club diagnose` показывает отложенное обновление.

Кнопка «Удалить книгу» открывает подтверждение: книга убирается из каталога и очереди, ожидающие напоминания останавливаются, тема и эссе сохраняются. Восстановление доступно через «Удалённые книги» в каталоге, кнопку в прежней теме или `/club library deleted`. События Discord не отменяются; автостатус после восстановления остаётся выключенным. Миграция 12 сохраняет все прежние книги неудалёнными. [Обновление и проверка на сервере](BOOKCLUB_FAST_CONTROLS_ROLLOUT.md).

Каталог открывается с текущей книги и десяти следующих книг в сохранённом порядке. Продолжение очереди, прочитанное и предложения находятся в отдельных разделах этой же темы. «Порядок чтения» открывает приватную панель организатора: выбор книги, перемещение выше/ниже, добавление предложения в конец очереди. Архив и текущая книга не переставляются этими кнопками.

Карточки не показывают внутренние идентификаторы, общий текст про камеры, список участников чтения и отдельный срок эссе. Длинные ссылки на файлы отображаются как «Читать PDF» и «Скачать EPUB». Исходные материалы в базе сохраняются. Встречи показываются ссылками на события Discord. Служебные идентификаторы остаются в SQLite и скрытых ID кнопок.

В Вестнике бот закрепляет отдельное сообщение «Как устроен книжный клуб». «Изменить формат» позволяет организатору менять правила, интервал между сдачей эссе и обсуждением (по умолчанию 24 часа), а также список повторяющихся событий. «История изменений» показывает автора, время и обе версии каждого изменения. Для закрепления нужно соответствующее право бота в канале; права автоматически не переписываются.

Даты выбранных повторяющихся синков читаются из Discord на обычной сверке. Они отображаются у текущей книги и в каталоге, но не становятся навечно привязанными встречами этой книги. Имена «Первый/Второй/Третий синк» не определяют этап книги. Индивидуальный план остаётся N встреч чтения + следующая встреча для эссе. По умолчанию N=3; можно задать 5 или другое число. Для автоматического назначения всех экземпляров плана ещё нужен выбор начальной встречи; пока отображается ближайшее расписание.

Для связанной индивидуальной встречи с типом «Обсуждение эссе» срок вычисляется автоматически за 24 часа до начала либо за интервал из формата клуба. При переносе, отмене, недоступности или нескольких подходящих обсуждениях старые уведомления отменяются. Ручное поле срока в `/club book_edit` и форме книги удалено.

Миграция 11 добавляет формат, историю его изменений, снимок расписания и журнал создания событий. Текущие статусы, очередь, теги и завершённые импорты не меняются. Новые нативные события тоже создаются без открытого служебного ID; потерянный ответ восстанавливается по сохранённому запросу, отправителю и границе списка событий, с сохранением проверки неоднозначности.

Проект библиотеки PDF/EPUB и предложения планов по объёму описаны отдельно: [источники, проверка полноты и планирование](BOOK_LIBRARY_DESIGN.md).
