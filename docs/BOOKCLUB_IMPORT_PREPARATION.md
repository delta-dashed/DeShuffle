## Сначала показать все источники и ознакомительные фрагменты

Команды выполняются разрешённым организатором в Discord. Ответы и JSON-файлы приватные. В `source` выбрать исходный канал `1523696063586893884` через Discord; `thread` принимает строковый ID, поэтому архивный тред можно указать независимо от списка подсказок.

```text
/club import inventory source:<исходный канал> page:1
/club import inventory source:<исходный канал> page:2
```

Каждая страница содержит до 10 тредов и прикладывает полный полученный JSON. Инвентаризация отдельно показывает активные/архивные треды, включение/исключение, уже перенесённые исходные сообщения и прогресс preview. Метка «не просмотрен из-за лимита» относится к чтению фрагментов, а не к отсутствию треда в перечне. Если перечень неполон из-за доступа или ошибки Discord, сначала устранить указанную причину; не объявлять 13 тредов подтверждёнными по одному совпавшему счётчику.

Сохранить явно разрешённое исключение:

```text
/club import prepare source:<исходный канал> thread:1546258784597315647 decision:excluded confirm:true
```

Показать ознакомительные фрагменты каждого из 11 оставшихся тредов. Название и автор на этом этапе не назначаются, новые книги и новые темы не создаются:

```text
/club import preview source:<исходный канал> thread:1540977150490837024

/club import preview source:<исходный канал> thread:1528059117967773888
/club import preview source:<исходный канал> thread:1525816608503627806
/club import preview source:<исходный канал> thread:1524729292737744936
```

Для каждого ответа с `continuation` выполнить указанное продолжение:

```text
/club import preview source:<исходный канал> cursor:<полученный токен>
```

Продолжать до завершения выбранного треда. Не совмещать `cursor` с `thread`, `before` или `after`: токен уже фиксирует место продолжения. На границе лимита следующее сообщение не теряется и не обрезается. Пустой фрагмент с продолжением может означать, что просмотрены сообщения бота или уже импортированные источники; он не означает конец архива. Если одно сообщение само не помещается в лимит, передать точную ошибку пользователю, не увеличивать лимит самостоятельно.

Ознакомительный фрагмент помечен `preparation_confirmed: false`, не содержит автоматически придуманных книг и не подходит для `scan`. Передать пользователю полный перечень, все полученные фрагменты и нерешённые вопросы о метаданных. Содержимое эссе хранить в закрытых артефактах на сервере; в Git и общие логи его не писать.

Серверный Codex может получить те же данные через существующий экземпляр `ArchiveImporter`, если у него уже есть безопасный способ выполнить код в окружении бота: `preparation.inventory(guild, actor_id, source_id)` и `preview(guild, actor_id, source_id, thread_id=..., cursor=...)`. Использовать только разрешённого организатора и штатные проверки доступа; не подменять пользователя и не отключать проверки. Не поднимать второй Gateway-клиент с тем же токеном ради этой операции.

## После человеческой проверки сохранить очередь

Включение требует подтверждённой пары `title`/`author` **либо** выбора существующей книги через `book`. Примеры ниже — шаблоны для уже одобренных человеком данных, а не разрешение автоматически включить весь список:

```text
/club import prepare source:<исходный канал> thread:<ID> decision:included title:<подтверждённое название> author:<подтверждённый автор> confirm:true
/club import prepare source:<исходный канал> thread:<ID> decision:included book:<книга из подсказок> confirm:true
```

Если данных недостаточно, оставить `pending`. Возврат на ручную проверку:

```text
/club import prepare source:<исходный канал> thread:<ID> decision:pending confirm:true
```

Выбор сохраняется по ID источника и треда, поэтому переименование тредов не сбрасывает его. Подтверждение хранит решение; исходные сообщения, существующий каталог и завершённые переносы не меняются.

После выбора выполнить preview всего исходного канала:

```text
/club import preview source:<исходный канал>
```

Этот режим читает только включённые и подтверждённые треды. Продолжать по каждому полученному `cursor` до конца очереди. Токен продолжает чтение внутри текущего треда, затем переводит к следующему; отдельные старые команды `thread/after` не заменяют продолжение всей очереди. Проверять `coverage`, `continuation` и предупреждения, а не число книг в одном JSON. Число книг относится только к подтверждённым книгам конкретного фрагмента; завершённая очередь не включает исключённые и неподтверждённые треды. Изменение выбора требует нового preview вместо продолжения устаревшей очереди.

Финальный отчёт серверного Codex: установленный commit, полный перечень активных и архивных источников, сохранённое исключение, ознакомительные фрагменты по каждому оставшемуся треду, подтверждённые человеком метаданные/сопоставления, неразрешённые пункты, полный прогресс очереди и доказательство неизменности бюджета и завершённого run. **На этом остановиться. Новый лимит запусков и `scan` пользователь согласует отдельно.**
