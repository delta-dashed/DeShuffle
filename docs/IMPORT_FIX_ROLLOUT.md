# Обновление бота после первого переноса эссе

Контекст для Codex на сервере. Репозиторий: https://github.com/delta-dashed/DeShuffle, ветка `feature/text-users-shuffle`. Требуется обновить работающий Docker Compose и исправить оформление завершённого импорта. ID конкретного запуска возьми из переданного контекста сервера или `/club import status`; не выбирай другой запуск автоматически.

## Ограничения этого обновления

- Не запускай `/club import scan`, `CodexRunner.analyze` или иной анализ архива. Израсходованный `max_runs=1`, прежний `budget_id`, резерв токенов и авторизацию нужно сохранить. Новый анализ требует отдельного решения владельца.
- Не меняй права ролей и каналов, ручные имена, теги, книги и привязки исходных сообщений. Не выполняй настройку с `repair_permissions:true`.
- Не удаляй исходные сообщения, форумные темы, ответы участников и созданные раньше пустые дубли. Исправление удаляет только проверенные служебные копии внутри прежних тем после подтверждения их новых копий.
- `.env`, содержимое `/data`, Codex auth, тексты эссе и резервные копии остаются на сервере вне Git и публичных логов. Не выводи полный Compose config или переменные окружения: они могут содержать секреты.

## Обновление

1. Проверь текущую ветку, локальные изменения и настоящий Compose project. Сохрани изменения, если они появились; не используй reset/force. Получи обновления `origin` и выполни fast-forward ветки `feature/text-users-shuffle`.
2. Убедись, что один Discord-токен обслуживается только одним экземпляром бота. Ранее остановленный дублирующий контейнер не запускай.
3. Останови основной сервис и сделай новую закрытую резервную копию постоянного `/data` вместе с SQLite. Сохрани прежний volume, внешний конфиг импортера и отдельный профиль Codex. Не используй `docker compose down -v`.
4. Собери и запусти сервис в прежнем Compose project. Для проекта с прежним опциональным Codex CLI подходят команды ниже; сохрани серверные overrides, если они уже используются:

   ```sh
   docker compose build --build-arg INSTALL_CODEX=true --build-arg CODEX_VERSION=0.152.1 reshuffle
   docker compose up -d --no-build --no-deps reshuffle
   ```

   Для исправления эссе CLI не вызывается, но его установка сохранена для уже настроенного временного импортера. Профиль повторно авторизовывать не нужно.
5. Проверь запуск и миграцию 7, отсутствие новых ошибок, прежние значения бюджета и единственный работающий экземпляр. Миграция добавляет журнал восстановления планов, аудит замены копий и состояние временного открытия архивных тем; существующие записи сохраняются.
6. Проверь новые slash-команды. При необходимости владелец выполняет существующую `!sync`. Для обновления старых карточек с кнопкой **«Открыть моё эссе»** выполни `/club publish`. Команда включает публикации клуба, поэтому используй её для уже опубликованного клуба.

## Исправление завершённого переноса

Выполни от разрешённого организатора, подставив один и тот же ID вместо `RUN_ID`:

```text
/club import restyle run:RUN_ID
```

Команда сначала проверяет все темы, авторов, привязки, сообщения, вложения и доступы. Этот предпросмотр не отправляет сообщения, не вызывает Codex и работает при исчерпанном бюджете. Проверь, что перечислены именно ожидаемые темы. После проверки применяй разрешённое исправление:

```text
/club import restyle run:RUN_ID confirm:true
```

Текст и файлы отправляются вебхуком с сохранёнными ником и аватаркой автора в существующие темы. Discord не позволяет сменить отправителя у уже отправленного обычного сообщения: новые копии получают новые ID и появляются в конце темы. До удаления прежних служебных копий бот подтверждает новые сообщения, вложения и обновление шапки. Ответы людей остаются на месте. Если тема была архивирована, её архивное состояние восстанавливается, в том числе при повторе после сбоя.

Если команда остановилась, прочитай конкретную причину. Не обходи проверки SQL-правками и не удаляй публикации вручную ради повторного запуска. При потере подтверждения Discord повтор той же команды восстанавливает уже отправленные копии по сохранённым маркерам. Удалённый вебхук прежней шапки, изменённая копия или пропавшая часть требуют отдельного разбора; команда не должна молча восстанавливать удалённый текст.

## Проверка результата

- ID тем, авторы в `bc_essays`, привязки `bc_import_sources` и состояние запуска `done` прежние; бюджет и резерв токенов не изменились.
- Ник и аватарка автора есть у текста и сообщений с файлами. Служебные ссылки «Первое исходное сообщение» и «Оригинал сообщения» убраны. Ссылки, написанные самим автором, сохраняются. Маркеры `bc:...` остаются для восстановления без дублей.
- «Добавить своё эссе» открывает существующую перенесённую работу этого участника по книге. «Открыть моё эссе» доступна на карточках книги и встречи, показывает приватные ссылки и не создаёт темы. Уже существующие пустые дубли автоматически не удаляются.
- Исходные сообщения и ответы участников в новых темах не изменены. Повторный `restyle` не добавляет копий.

Завершённому запуску не нужны `restore` или повторный `apply`. Новая `/club import restore` предназначена только для будущих `failed`/`unknown`: принимает проверенный человеком JSON из исходного снимка с отдельным подтверждением, записывает аудит и возвращает запуск к `review` без нового запроса модели. `/club import preview` позволяет подобрать ограниченный тред или диапазон без расхода квоты.

В итоговом сообщении укажи установленный commit, проверенные темы, результат исправления и неизменность бюджета. Не утверждай, что Discord проверен, если удалось только обновить контейнер.
